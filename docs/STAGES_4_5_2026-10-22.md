# Stages 4–5: Minecraft Java 1.12.2-style held items and command/touch controls

## Scope
This work is deliberately limited to the user's fourth and fifth stages. Mining/world physics (1–3) remain as previously deployed. Lighting, death overlays and other later stages (6–7) are not revised here.

## Stage 4 — hands, blocks and tools
- Keep first-person rendering separate from the world camera with an independent projection and a right-arm mesh. Reduced the right-arm Z rotation to avoid the previous sharply bent presentation.
- Read `display.firstperson_righthand` from the owner-provided private Java 1.12.2 JAR item models, following safe `parent` chains. Resolve item model transforms for supported items and blocks only. These numbers are stored locally, never published with copyrighted Minecraft files.
- Build 3D held models from private validated block element geometry/UVs for the supported blocks. The original block-model element units are normalized from 1.0 block to the 0.28-view scale previously used by the renderer, avoiding oversize held blocks.
- The independent, publicly available fallback displays different low-poly pickaxe/axe/shovel shapes. When the user imports their owned JAR item sprites, the first-person viewer uses those local item textures and the source model's display transform approximation.
- Automated unit checks cover parent inheritance and invalid numeric transforms, distinct tool classes, block geometry, held model normalization and preserved arm rendering. The deployed Chromium WebGL fixture compares different tool silhouettes and captures an owner-model-style held block screenshot using **synthetic, independently authored** asset data.

## Stage 5 — Java PC command UI and mobile movement
- Pressing `/` in gameplay opens a bottom-aligned command strip prefilled with slash. Tab completion and ArrowUp/ArrowDown suggestions are preserved. Enter submits and closes even when invalid; Esc closes without execution. Command output is appended to a compact in-game chat history rather than keeping a website modal open.
- On devices with a virtual keyboard, the command strip tracks `visualViewport` to stay above the keyboard, and the mobile game buttons hide while commands are entered. IME composition Enter does not submit before the composition completes.
- Mobile D-pad walking, jump hold, sneak toggle, drag-to-look, long hold-to-mine and tap-to-interact remain supported. Movement/jump buttons now mark pressed state and release on pointer up/cancel, lost capture, window blur, and opening the command, pause or inventory menus. This prevents stuck movement after switching UI.
- The deployed Chromium browser check opens and closes commands with Enter and Esc on PC and touch-screen configurations, checks mobile button visibility and touch press/release, and captures screenshots on desktop and portrait/landscape sizes.

## Limits and copyright
No original Minecraft PNG, JAR, proprietary class file or font was uploaded to public GitHub. Users who have legally obtained `1.12.2.jar` can keep it privately cached for their own device; other visitors see original site assets. Our Three.js first-person render, arm poses, mobile controls and command UI are approximations; pixel-perfect parity with the original Java 1.12.2 client requires controlled side-by-side screenshots and more of the original model render pipeline. Browser and test success alone cannot prove that parity.
